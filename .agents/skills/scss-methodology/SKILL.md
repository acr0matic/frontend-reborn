# SCSS-методология проекта

Применяй правила к `src/scss/**/*.scss`. Для создания страницы используй `/new-page`, для проверки — `/verify-page`; этот скилл описывает границы, нейминг и стилистические инварианты.

## Перед изменением

1. Прочитай ближайшие реализации и `src/scss/settings/_vars.scss`.
2. Проверь, к какому уровню относится стиль: глобальный каркас, общий partial, компонент или scoped-стиль секции.
3. Не создавай новый атом или компонент, если существующий можно расширить модификатором.

## Область видимости и BEM

- Page-стили размещай под ID секции: `#cp-home-hero { .hero { ... } }`.
- `&__element` пишется только внутри блока; `&-suffix` используй для составных имён.
- Максимальная глубина вложенности — два уровня. Конструкции вроде `.block__body__title` запрещены.
- `g-*` — глобальный каркас, `b-*` — переиспользуемый контентный блок, `c-*` — интерактивный компонент, `m-*` — микро-элемент.
- Карточки всегда называются `card-{type}`, элементы сохраняют тот же префикс: `.card-news__title`.
- Базовые атомы (`.button`, `.input`, `.link`, `.icon`, `.image`, `.container`, `.section`) остаются без префикса.
- Состояния, которыми управляет JS, называй `is-*`; поведение привязывай к `data-*`.
- Общие роли секции — `.section__header`, `.section__title`, `.section__text`, `.section__action`; не создавай scoped-дубли вроде `.hero__title` для той же роли.
- Типовой фон и ритм секции оформляй `.section--bg` и `.section--white`.

## Переменные и токены

- CSS custom properties (`--*`) используй для значений, меняющихся в media queries.
- Sass-переменные (`$*`) используй для констант: цвета, веса, transition и z-index.
- Визуальные уровни типографики задаются токенами `--font-title-large|medium|small`, `--font-text-large|big|regular|small`; межстрочные интервалы — `--line-height-large|medium|small`.
- Семейство и веса подключаются через `$font-default` (`settings/_fonts.scss`) и `$weight-*`; не подменяй их локальными magic values.
- Палитра задаётся через `$palette-*`, роли — через `$color-text__*`; для ссылок используй `$link-color` и `$link-hover-color`.
- Шкалы токенов отступов в проекте нет — значения бери из дизайн-макета литералами и не выдумывай самодельные переменные.
- Контейнеры используют `$container-max-widths`, `$container-wide-width` и `$container-padding` из `settings/_container.scss`; не дублируй их локальными значениями.
- Слои используют `$z-index-header: 50`, `$z-index-overlay: 51`, `$z-index-menu: 52`, `$z-index-modal: 53` из `abstracts/variables/_z-index.scss`.
- Используй существующие цвета, типографику, брейкпоинты и контейнеры из `settings/`; magic values не добавляй без необходимости.
- Высота секции формируется контентом и `padding`; `height` и `min-height` для вертикального размера не используй. Исключение — `min-height: 2lh` для выравнивания заголовков карточек.

## Адаптив и layout

- Responsive-правила описывай через `@include mq(...)`.
- Media query располагай первым внутри конкретного селектора, а базовые свойства — после него:

```scss
.card {
  @include mq($until: tablet) {
    flex-direction: column;
  }

  display: flex;
}
```

- Для каждого селектора используй собственный media block; общий `@include mq`, собирающий несколько селекторов, запрещён.
- Для карточечных Grid-треков используй `minmax(0, 1fr)`.
- Для пропорций изображений используй `aspect-ratio`, а не фиксированную высоту.
- Отступы между соседями одного уровня задавай `gap` на flex/grid-родителе, а не `margin` на детях.
- Округляй размеры до чистых значений и сохраняй существующую шкалу проекта.

## Вендорные стили

- CSS библиотек подключай централизованно в `src/js/app.js`, не в компонентных SCSS-файлах.
- Классы, которые создаёт библиотека, не дублируй своими. Для Swiper используй `.swiper-button-prev`, `.swiper-button-next`, `.swiper-button-disabled`, `.swiper-slide`, `.swiper-pagination`.
- Расширения библиотек размещай в `src/scss/vendors/extend/`, переопределения — в `src/scss/vendors/override/`.
- При изменении стандартных кнопок Swiper явно сбрасывай конфликтующие `position`, размеры, `margin-top` и скрывай `::after`, если добавляешь собственную стрелку.

## Проверка

После изменений запускай:

```powershell
npx stylelint "src/scss/**/*.scss" --fix
```

Затем проверь, что файл подключён в нужном `_main.scss`, селекторы совпадают с HTML и page-стили не выходят за ID секции.

## Чек-лист

- [ ] Выбрана правильная область видимости и нет нового дублирующего атома.
- [ ] BEM-путь плоский, глубина вложенности не превышает двух уровней.
- [ ] Использованы токены проекта, а media queries находятся у своих селекторов.
- [ ] Layout построен потоком через Grid/Flex, `gap`, `minmax` и `aspect-ratio`.
- [ ] Вендорные классы и файлы находятся в правильных местах.
- [ ] Stylelint запущен с `--fix`.
