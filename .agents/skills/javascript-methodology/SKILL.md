# JavaScript-методология проекта

Применяй правила к `src/js/**/*.js`. Для публичных контрактов компонентов сверяйся с `DOCS.MD`, для проверки страницы — с `/verify-page`.

## Размещение модулей

- `src/js/app.js` — точка входа: стили и `global/init`.
- `component/ui|input|form` — переиспользуемые контроллеры компонентов, элементов ввода и форм.
- `layout/page/{page-id}.js` — поведение конкретной страницы.
- `layout/section/`, `layout/block/`, `layout/modal/` — поведение соответствующей сущности.
- `utils/` — небольшие утилиты без собственной разметки.
- `animation/` — сценарии под `data-animation`; папка и зависимость (`gsap`) создаются при первом использовании — их сейчас нет.

## Lifecycle и регистрация

Переиспользуемые компоненты реализуют единый lifecycle:

- `init()` — первичная инициализация;
- `update(root)` — поиск и обработка новой или изменённой разметки;
- `destroy()` — снятие listeners, observers и очистка состояния.

Компоненты регистрируй через `app.register()` в `src/js/global/init.js`. Экспортируй классы и контроллеры по умолчанию, методы документируй JSDoc в стиле существующих модулей.

## Page guard

Page-модуль сначала ищет корень страницы по ID и ничего не делает, если его нет:

```js
const page = document.querySelector('#cp-cart');

if (page) {
  // Поведение страницы работает только внутри найденного корня.
}
```

Не размещай побочные эффекты на уровне модуля до проверки корня. Scoped-поиск выполняй от `page` или секции, а не от `document`, если поведение не глобальное.

## DOM-контракты и очистка

- Поведение привязывай к `data-*`, состояния отражай классами `is-*`.
- Новые интерактивные компоненты должны использовать уже существующие публичные контракты и `window.App`, если они подходят.
- Listeners и observers обязательно снимай в `destroy()`; для групп listeners предпочитай `AbortController`.
- После AJAX-вставки вызывай `window.App.update()` или событие `app:update`, если это соответствует контракту компонента.
- Не оставляй отладочные `console.log` и не меняй публичный API без отдельной задачи.

## Шапка

`Header` в `src/js/layout/header.js` пишет высоту `#header` в CSS-переменную `--header-height` на `:root` и обновляет её на resize. Отступы секций под фиксированной шапкой бери из этой переменной.

## Анимации

GSAP в зависимостях нет — ставится через `yarn add gsap` при первом сценарии. Контракты для сценариев:

- Для общих сценариев используй `data-animation="тип"` и обрабатывай все найденные элементы через `querySelectorAll` и `for...of`.
- Для ScrollTrigger сохраняй проектный контракт `toggleActions: 'play none none reverse'` и `ease: 'power2.out'`, если конкретный дизайн не требует другого.
- `data-animation="text-reveal"` ставь на блочную обёртку текста. Для flex-ссылки с иконкой анимируй `.section__action`, а не саму ссылку.
- На контейнере с `data-editor` сплитируй прямых потомков и не вешай атрибут на внутренний `p`.
- Учитывай `prefers-reduced-motion` для новых анимационных сценариев.

## Lazy loading

Используй один из двух контрактов и не смешивай их:

- `.lazy` + `.lazy__item` + `data-src` — изображения с прелоадером;
- `.lazy-simple` — простые фоновые элементы без прелоадера.

Для большого hero-фона допускается `.lazy__item--blur`; для карточек и контентных изображений этот модификатор не используй.

## Проверка

После изменений запускай:

```powershell
npx eslint "src/js/**/*.js" --fix
```

Проверь импорт модуля в `src/js/app.js` или регистрацию в `global/init.js`, наличие page guard, корректный lifecycle и отсутствие утечек listeners/observers.
